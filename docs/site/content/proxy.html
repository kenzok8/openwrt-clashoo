代理模式与 DNS

这两块最容易混：代理模式决定路由器怎么接管流量，DNS 设置决定域名怎么解析。流量不通先分清是哪一层出的问题。

三种代理模式

模式怎么接管什么时候用
Fake-IP给需要代理的域名分一个虚拟 IP（198.18.x.x），内核收到再还原成域名转发默认。兼容性好、配置简单，绝大多数家庭路由器够用
TUN建虚拟网卡接管流量需要更完整的接管，或某些应用在 Fake-IP 下不听话
MixedTUN 的另一种网络栈（mixed stack）System / gVisor 表现不稳、虚拟机环境兼容性差时试它

TUN 系（含 Mixed）的前提：设备有 /dev/net/tun，容器或 PVE LXC 还要宿主机放行 TUN。

透明代理细分

Clashoo 把 TCP、UDP、网络栈拆开配，不必一个模式全包：

项目可选说明
TCPRedirect / TProxy / TUNRedirect 最省事，TProxy 兼容性好，TUN 接管最彻底
UDPTProxy / TUN走代理的 UDP 出问题时，可以只把 UDP 443 拦掉让应用回落 TCP
网络栈gVisor / System / Mixed只有 TCP 或 UDP 选了 TUN 才生效

另有「禁用 QUIC GSO」开关，个别网卡驱动下 GSO 会导致 UDP 分片异常。

选了 TUN 但设备不支持时，Clashoo 会自动降级到兼容模式继续跑。能上网就说明只是没吃上 TUN，不是配错了。

局域网 ACL

可以按 IPv4、IPv6、MAC 分组，分别控制两件事：是否接管 DNS、是否走代理。想让某台设备（比如电视盒子）绕开代理，或者反过来说「只让这台走代理」，都在这一块。

IPv6 的两个开关别搞反

基础 DNS → IPv6 解析透明代理 → IPv6 DNS 劫持
作用对象Clashoo 内核自己解析域名时查不查 AAAA局域网设备发出的 IPv6 DNS 请求要不要被接管
关掉的后果内核基本只拿 IPv4 地址设备可能绕过 Clashoo，分流规则失效、DNS 泄漏

即使不用 IPv6 代理，也建议保留 IPv6 DNS 劫持。运营商下发的 IPv6 DNS 一旦绕过 Clashoo，分流和 Fake-IP 都会失灵。

防泄漏

  • 阻止国内 DNS 解析国外域名
  • 阻断 DoT / DoQ，避免应用自带加密 DNS 绕过分流
  • 节点域名单独指定 DNS，防止节点域名被规则误分流
